# 项目状态

## 2026-11-21 实机记录

| 项目 | 结果 |
| --- | --- |
| TUNIC 暂停菜单花屏 | 已修复。旧运动估计把菜单光照跃变当成运动，六次打开均捕获到破碎帧。新 shader 使用屏幕空间重建，六次打开和六次关闭均捕获到一个清晰的生成帧，12 个编号与 GPU 已提交作业一致。 |
| TUNIC 读档白屏 | 按项目验收口径关闭。修正 Vulkan 跨设备源图像的读取等待和复用等待后，从启动开启补帧正常读档。旧版复跑也成功，因此最初 Unity 零长度缓冲区错误与同步缺口的因果关系仍未确认。 |
| ANVIL-S W8A8 | 当轮 TUNIC 的 HTP daemon 完成 3,536 次执行，零错误。Adreno 回放中 12 组菜单帧进入屏幕空间重建，17 组正常运动素材继续运行原路径。 |
| 30→60 FPS | 《亡命迪斯科》早期 19.20 秒运动样本捕获到 572 个生成帧编号，顺序正确。测试是 Gamescope 采集层，强切场景和物理面板仍待复核。 |
| 60→120 FPS | TUNIC 先前 5.80 秒海滩样本在 PipeWire 层为 118.91 帧/秒，生成帧编号核对 341/345。同一测试环境的真实帧对照为 59.97 帧/秒。图形修正版在约 12.8 秒运动区段提交 755/756 次，仍有采集队列丢失和交换链空闲图像不足。 |
| 软件响应 | TUNIC 图形修正版的暂停输入到 Gamescope 捕获 P50 约 125 ms、P90 约 141 ms，各有六次动作。它未测面板扫描，也未测输入到光子。 |

实际验证使用 Odin 3、ArmadaOS、Gamescope、Adreno 830、Hexagon v79 和私有 HTP daemon。Vela 与 LSFG 在该 TUNIC 对照中关闭。测试结束后恢复了 Steam 启动项和云存档设置，并核对源存档。没有通过这些测试验收 1080p、HDR、其它掌机或 Vela/ANVIL 并行运行。

下一步在 TUNIC 60→120 FPS 下复测持续运动，先取消采集队列丢帧，再区分生成提交、合成器锁存与实际显示。若白屏再次出现，采集 Unity 首次零长度缓冲区调用和同一时刻的 Vulkan 提交时间线。
